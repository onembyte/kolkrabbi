What it does.
What comes next.

Kolkrabbi is being built one independently tested checkpoint at a time. This page keeps the promise honest: working behavior is separated from settled design and future work.

  • Available nowIn the current source and test suite.
  • Designed, not shippedThe contract is settled; implementation remains.
  • PlannedOn the roadmap and still subject to hardening.

01 / WORKING

Useful already.

These capabilities exist in the current binary and are covered by the offline test suite. Anything a release has not yet carried to the installer is marked below.

Available nowMODES

Chat, code, and agent modes

Chat stays tool-free. Code runs the focused tool loop. Agent plans the work as tasks with real dependencies, routes each one, runs the independent ones concurrently, and synthesizes a single answer that says what failed.

Available nowEFFORT

One effort dial

low, medium, high, and max select the model tier and set the tool-round limit, the shell timeout, and how many tasks an orchestrated run may open. The older quick/standard/deep/ultra words still work.

Available nowMODELS

Gateway, subscription, or local

OpenRouter works today, and an OpenAI-compatible base URL points Kolkrabbi at Ollama, LiteLLM, vLLM, or another compatible endpoint — used without a key, because the OpenRouter key is bound to openrouter.ai and is never sent anywhere else. A Claude or Codex plan answers turns through the user's own vendor CLI, and /model moves the provider with the model.

Available nowDISCOVERY

Every vendor mapped before it is offered

On every start and every login Kolkrabbi asks each connector what it lists today — codex debug models for Codex, a gateway preview of the Claude families for a CLI that lists nothing — and only then shows them. /pmodels says how each row is known: listed, verified once a turn has answered on it, gone when the vendor stopped listing it, in which case it is refused by name. Kolkrabbi's own list only ranks; the vendor decides what exists, so a renamed model tomorrow is a row that changes, not a build that breaks.

Available nowKEY

Safe key onboarding

/key <key> classifies and masks the value, refuses known subscription tokens, verifies OpenRouter when reachable, and stores credentials outside config.

Available nowTOOLS

Six focused tools

Read, list, write, edit, and shell execution cover the code loop, and a sixth asks you a question when the answer is genuinely yours. File paths are confined to the project, three permission tiers — ask, auto-approve, full-auto — decide how much happens without a prompt, and a binary is described rather than sent while a large file says how to page through the rest.

Available nowSESSIONS

Sessions you can find again

Conversations save atomically and resume. kolk -r resumes the work done in this directory, and sessions can be searched, renamed, forked, and exported. A session earns a readable name on its own once enough has happened.

Available nowCONTEXT

A long session that does not fall over

The context window is measured from provider-reported tokens. Compaction fires at a turn boundary and says what it gave up, /compact undo puts the conversation back, and a turn refused for length is recovered instead of lost.

Available nowMEMORY

Standing notes, in layers

KOLKRABBI.md or AGENTS.md in the working directory carries project instructions, and /remember writes one line of personal guidance beneath it — only when asked, never as a silent edit to a project file.

Available nowUNDO

Take a turn back

In a git repository every turn snapshots the whole working tree into a store outside it, so /undo takes back a formatter, a codegen step or an rm that ran through bash — not only Kolkrabbi's own edits. Your index, HEAD, stash and reflog are never touched. Outside a repository it falls back to copying files before they change. /diff shows what this session changed, /undo takes back a turn's files and its conversation together, and /rewind restores the files alone.

Available nowLOCAL

Private usage history

Token, cost, latency, mode, effort, and optional 1–5 ratings stay in local JSONL. /stats prints the table and /dash serves the same numbers to a loopback-only page. Neither sends telemetry.

Available nowUPDATES

Updates you can verify

/update finds the newest release, checks its signed checksum before trusting a byte of it, and replaces the running binary atomically, so an interrupted update leaves the old one working.

Available nowLOOP GUARD

A turn that is going nowhere stops

Three identical tool calls returning identical results are a loop, not a fourth attempt. The call is never made a third time: you are asked whether to run it again, and in /full-auto the turn stops and says what it stopped. Alternating calls count too — remove, list, remove, list is a cycle even though no call ever follows itself, and a nine-call window sees rotations a consecutive counter misses. A failing test whose output keeps changing is progress and is left alone.

Available nowASK

A question you answer by picking

When a decision is genuinely yours — which database, which of two designs — you get a list, not a paragraph. Arrows move, enter takes the highlighted row, the number beside a row takes it outright, escape backs out. The recommendation is first, so enter alone is a real answer. Dismissing is not choosing: it is never reported as picking the first option.

Available nowUNINSTALL

Leaving is one command too

kolk uninstall lists every path it will delete, what each one holds and how big it is, then asks once. --keep-data spares your key, settings and sessions for a reinstall. Anything that is not an explicit yes is a no, a closed input included, so a script can never quietly delete your key.

Available nowGIT

It knows what you have not committed

A turn begins knowing which files differ from the last commit, so advice is about the tree you actually have. /commit drafts a message from the staged diff and /pr drafts a title and body — both hand you the command and neither runs it.

Available nowDOCTOR

Ask what it can see

/doctor reports keys, directories, terminal and reachability — what it found, never what it found with. --debug writes a scrubbed log for one session and tells you where it is, so a bug report can carry it.

Available nowSESSIONS

See which session is waiting for you

kolk sessions and the dashboard mark a session stopped at a permission prompt, warn when two live sessions share a directory, and show what each has spent. A bash command that starts a server says which port it took.

Available nowCORE

Small, tested core

A static Go binary, a standard-library-only core, offline end-to-end tests, strict architecture rules, and five target builds protect the working surface.

02 / ACCESS

Your account, your key, your choice.

Every authentication path is built around a hard boundary: Kolkrabbi does not capture or reuse a subscription credential owned by another tool.

Available nowANY KEY

Any supported API key

/key <key> infers the provider from the key's own shape, and /key <provider> <key> states it outright for CI or an uncommon format. Reading the key from stdin keeps it out of shell history.

Available nowCLAUDE

Claude Agent subscription

Kolkrabbi hands sign-in to the user's own unmodified claude CLI and runs it as a backend: one persistent process per session, scrubbed frames, per-turn cost, and an effort level that steps down to what the plan actually offers. -P full-auto reaches the child as the vendor's own permission bypass, said once per session with what it costs, so a delegated run can execute commands and not only edit files. No subscription token is stored. Starting a session still expects a gateway key; removing that is an open decision.

Available nowCODEX

Codex subscription

Kolkrabbi hands sign-in to the user's own codex CLI and runs it as a subscription backend. Agent mode gives each subagent its own vendor process while the session keeps the provider, model, and plan limits visible.

Available nowONE SESSION

Backends in the same Kolkrabbi session

Switching between a gateway model and a subscription plan mid-session keeps the local transcript and project context, moves the provider with the model, and releases the one it retires. An unusable plan model refuses with its reason instead of failing quietly.

Available nowLOGIN

Login without lock-in

/plans lists what each provider plan exposes and /plogin filters them as you type. Login is handed to the provider's own CLI, never spawned while Kolkrabbi owns the keyboard, and a clean exit is recorded as unverified until a real turn proves it. Optional browser login is still planned.

DesignedSECRETS

Inspectable credential sources

Keys live in a locked, permission-checked manifest outside config today. The wider chain — environment, provider environment, one named store, a visible first-hit order, and opt-in OS keychain storage — is settled design that is not built yet.

03 / CONTINUITY

When a limit hits, the work stays.

Only the narrow part of this policy ships today. The rest will prefer explicit, explainable continuation over a silent change in model or billing path.

Available nowRETRY

Survive a temporary refusal

A provider failure before the stream starts is classified, a temporary 429 is retried on a bounded schedule, and a free model that is out of capacity rotates to the next eligible one. Nothing silently changes the model you are paying for.

DesignedDETECT

Know which limit stopped work

A subscription limit, account quota, endpoint capacity problem, budget stop, and model refusal remain distinct. Reset times and cooldown scope are preserved when available.

PlannedRECOMMEND

Explain the next move

Kolkrabbi will preserve the turn, say which backend stopped, and show how the project continues with the best-rated eligible configured model for that task.

PlannedCHAIN

Respect every configured option

The continuation chain will consider eligible subscription and metered backends in priority order while skipping known cooldowns instead of repeatedly hitting a cap.

PlannedSAFE DEFAULT

Ask before free fallback

After configured subscription and paid options are unavailable, Kolkrabbi will ask before continuing with a free model. The model, tradeoffs, and retained context are shown.

PlannedAUTO

Automatic switching

An opt-in policy will follow the same visible eligibility and cooldown rules without asking at each switch. Silent auto-switching is never the default.

PlannedPAUSE

Stop honestly when all limits are reached

If no eligible backend remains, the session pauses with reset information and a resume path. It does not discard work, loop through capped accounts, or pretend success.

04 / WORKFLOWS

More capable, still calm.

Advanced behavior remains optional. The first run stays install, key, and use.

Available nowROUTING

Task-aware model routing

A planned task carries a kind, the kind resolves to a named model slot, and the slot to a model — printed with the plan before anything runs. The orchestrator itself takes a slot too, so planning and synthesis need not use the model that does the work.

Available nowLANE

The model you pick is a ceiling

/mode agent prints the lane an orchestrated run may spend on — claude-fable → claude-opus → claude-sonnet → claude-haiku from the top rung — and trivial work is routed below the ceiling, never above it. A rung that will not open falls back to the model you selected, announced; nothing signed in below means everything runs on the ceiling, and the lane says what a sign-in would unlock.

Available nowAGENTS

Orchestrated agent runs

Independent readers run three at a time across the dependency graph while anything that may write is serialised. A failed task is reported instead of discarding the run, the answer says what is missing, and the spend is shown as it goes against an optional ceiling. Worktree isolation and a dedicated critic are still planned.

Available nowFREE

Computed free-model defaults

A cached live catalog ranks zero-cost, tool-capable models and prefers the strongest coding-oriented one for a session that names no model. A saved model, a flag, or a real effort-tier map still wins, because those are explicit choices.

Available nowSAGA

Careful long-running progression

Include /saga in a normal request to advance one bounded chapter at a time — plan, act, verify, checkpoint, report — with the project's own tests as the gate, a commit only on green, and a chapter limit, dollar budget, timeout, and doom-loop detector around it. One request is one wake: the saga keeps the goal it started with, text that differs becomes a note for that wake, a saga with nothing left to plan says so, and the next goal archives the finished artifact beside the new one — no run, resume, status, or stop subcommand exists.

Available nowCODE

Deeper code mode

An edit shows its diff before you approve it, @ completes file mentions against the project, /plan is a read-only mode built out of the permission rules rather than a second system, and the status line carries context and cost.

Available nowLOCALIA

Local models, planned before pulled

/localia reports what this machine can actually run — accelerators, RAM, free disk — and shows every number behind a fit decision, refusing what does not fit instead of degrading into swap. A pull asks first, then goes through the Ollama you already have; kolk never installs one.

Available nowCOMMANDS

A file is a command

Drop review.md in .kolk/commands/ and /review exists. The body is the prompt, $ARGUMENTS is placed or appended, the project's file beats your own, and a command cannot take the name of a built-in. An existing .claude/commands directory is read as-is, so command files you already wrote work without being moved or converted.

Available nowHOOKS

Hooks you agreed to

Run a formatter after an edit, a notification at the end of a session. Each command is confirmed once, the permission floor refuses what it always refuses, and a hook that fails or hangs is reported without costing the edit it followed. Hooks declared by a repository are listed in full and confirmed before any of them runs — cloning is never enough to execute anything.

PlannedMCP

External tool servers

Permission rules already name them — allow mcp(github__*) governs one server and nothing else — and the cost of tool schemas is measured and budgeted. The transports themselves are still to come.

05 / SAFETY

Local by default. Explicit at the edges.

Safety claims are only useful when architecture and tests can enforce them.

Available nowCONFIRM

Confirm side effects

Three tiers are the whole model: ask confirms every change and command, auto-approve edits inside the project but still asks before commands, and full-auto stops asking. No tier removes the floor — credential files, system directories, and unrecoverable commands are refused in all three.

Available nowRULES

Permission rules and path jail

File tools resolve against the project root, symlinks first, and reaching outside asks. Rules such as allow bash(git *) apply by tool and pattern with last match winning, kept for this session, this project, or everywhere — and the prompt shows the rule it would keep before keeping it.

Available nowREDACT

Secrets stay out of model context

Every tool result is scrubbed at one chokepoint, including secrets that carry no vendor prefix, and credentials move through opaque handles that cannot be printed by accident. Orchestrated work never prompts: what its tier would ask about is refused, with the way to allow it.

Available nowNETWORK

Delegated children say what they can reach

Each subagent's network access is decided once — from subagent_network (auto gives it to research tasks only, on, off), the task's kind, and whether the vendor's child has a switch at all — and the briefing, the status line, and the process envelope are all rendered from that one decision. A Codex child is told both ways; a Claude child has no switch, so it is declared rather than claimed. Both child paths drop credential-shaped variables, the vendor's own API key included on purpose, while ordinary build variables survive.

Designed, not shippedSANDBOX

OS-level execution sandboxes

OS-level isolation on supported Linux and macOS targets is accepted v1 scope, with a shared refusal contract and native negative tests required before it can be called available. The current binary still relies on its in-process path, permission, and capability boundaries; full-auto inside a future sandbox remains distinct from unrestricted host access.

Available nowPROTOCOL

Language-neutral event protocol

One versioned envelope, typed payloads, golden frames, and a CI guard that fails a contract change without a changelog entry. CLI, daemon, and future clients read the same bytes; the event vocabulary keeps growing under those rules.

Available nowGATES

Budgets and offline gates

Tests, lint, architecture checks, platform builds, binary-size and startup budgets, installer safety, and release contracts run without spending model credits.

06 / INTERFACES

One core, more places to use it.

The terminal remains first. Later clients attach to the same versioned core rather than rebuilding model behavior independently.

Available nowCLI

Four commands outside, everything inside

Outside a session there are four commands and no more: kolk sessions, kolk serve, kolk uninstall, kolk help — plus kolk to open a session and kolk -r to resume one. Everything else is a /command inside the session, a retired verb says where it went instead of reaching a model, and kolk help is the front door: what it is, the build identity line, the licence, both surfaces in full. Scripts still get a one-shot prompt, strict exit codes, and a streaming JSON output mode.

Available nowTUI

Full terminal UI

A persistent multiline composer, live tool and activity status, streamed replies, diffs rendered line by line before you approve them, @ file completion, and a status line carrying mode, model, effort, context, and session cost.

PlannedTHEME

Themes

NO_COLOR is already honored. Multiple terminal themes and a quieter presentation will change appearance without changing behavior or requiring setup.

Available nowDASH

Local model dashboard

/dash serves a loopback-only page rendered entirely on the server — no script, no assets, no network — showing spend, tokens, latency, ratings, and recent sessions with what each one cost. The store stays a plain local file.

Available nowDAEMON

Attachable local service

kolk serve carries byte-identical event frames over NDJSON, child stdio, and HTTP server-sent events, with replay from a last-seen event id and a conformance test that proves the three surfaces agree.

PlannedDEVICES

Desktop, iPad, Android, and Windows

Thin desktop and mobile clients plus complete Windows support arrive as additive frontends and platform ports on top of the protocol and service surfaces above.

07 / REACH

Off the machine that started it.

Remote access begins with the bind and the credential, not with the feature. A session you can reach from your phone is a session someone else could reach too.

Available nowBIND

No open port without a credential

A wildcard address is not loopback, and serving one without a token is refused before the socket opens. Every route needs the token except two that say nothing, and widening that set now fails a test.

Available nowPAIR

Pair a device with a short code

A six-digit code is armed for a couple of minutes, used once, and capped in attempts, on a route that does not exist the rest of the time. This is the server half: pairing is an HTTP call today, and the app that would make it a two-second gesture is below.

Available nowTOKENS

One revocable token per device

Each paired device gets its own token, stored only as a hash, and a device token ranks below the operator's: it can read the stream, while steering is a separate, higher grant. kolk devices lists paired devices, and kolk devices revoke <id> withdraws one.

Available nowREACHABILITY

Say who can reach this port

Starting a server prints how to reach it and who else can — the tailnet address first when there is one, the local network named as such when there is not, and the one-line SSH tunnel for a loopback bind.

Available nowAPPROVE

Answer a prompt from elsewhere

The server accepts it: a token-gated event stream with replay, and a route that resolves a pending permission request from a device that holds the steering grant. Nothing first-party sends that request yet, so today this is an API you could drive yourself rather than a thing you do from your phone.

PlannedCLIENT

Something to use it from

The protected surface above is built and tested; what is missing is the thing that speaks it — an authenticated view of a running session that shows the stream and answers a prompt. Until that exists, this section is a server waiting for a client.

PlannedMANY

Many sessions, one view

A client that lists every session on the machine, steers any of them by sending a turn, and reports what source control and the running workspace are doing is the next stretch of this road.
