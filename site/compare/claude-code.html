Kolkrabbi
vs Claude Code

Claude Code is Anthropic's agentic coding tool: it reads a codebase, edits files, runs commands, and runs in the terminal, in VS Code and JetBrains, in a desktop app, on the web and on a phone. It is proprietary and runs Claude models, across six deployment paths from the Anthropic API to Bedrock, Vertex and Microsoft Foundry. Kolkrabbi is an open-source terminal coding agent that is not tied to one vendor's models: it runs anything on OpenRouter, a local model on Ollama or vLLM, or the Claude and ChatGPT subscriptions you already pay for, by driving each vendor's own CLI.

Every claim below was checked against primary documentation on 2026-09-03. Both projects move quickly. If something here is out of date, it is a bug — say so.

01 / WHERE KOLKRABBI IS BEHIND

What Claude Code does better.

This section comes first on purpose. A comparison that opens with its own strengths is an advertisement, and you should not trust the rest of it.

Kolkrabbi does notMCP

No MCP servers

Claude Code speaks MCP, so it reaches Jira, Slack, Drive and anything else with a server. Kolkrabbi does not yet. If your workflow depends on MCP, this is the difference that matters most.

Kolkrabbi does notSURFACES

The terminal, and only the terminal

Claude Code runs in your IDE, a desktop app, a browser and a phone, and a session moves between them. Kolkrabbi is a terminal program; a remote device can watch a session and answer its permission prompts, but it cannot start one.

Kolkrabbi does notSANDBOX

No execution sandbox

Kolkrabbi has permission tiers, a path jail and confirmation rules, but no OS-level sandbox around the commands it runs. That work is accepted and unshipped.

Kolkrabbi does notWINDOWS

macOS and Linux only

Claude Code supports native Windows and WSL. Kolkrabbi cross-builds for Windows in CI and does not support it.

Kolkrabbi does notSCALE

One person, one codebase

Claude Code is a funded product with a team, a release channel that auto-updates, and skills, hooks and subagents that have been through many more hands than Kolkrabbi's have.

02 / WHERE KOLKRABBI IS AHEAD

What Kolkrabbi does differently.

Not better at everything — different in specific ways, each of which you can check in the source or in the first ten minutes of using it.

Kolkrabbi has itMODELS

Not one vendor's models

Claude Code runs Claude. Kolkrabbi runs whatever OpenRouter lists, a local model on Ollama or vLLM, or Claude and ChatGPT through their own CLIs — and lets you switch mid-session.

Kolkrabbi has itSUBSCRIPTIONS

Both subscriptions, one terminal

If you pay for Claude and for ChatGPT, Kolkrabbi can run turns on either, and switching between a gateway model and a plan mid-session keeps the transcript and the project context. It never sees, stores or refreshes either credential: each vendor's own CLI does the login, and Kolkrabbi drives that CLI as a subprocess. One caveat, because it is the first thing you would hit: starting a session still expects a gateway key even when a plan answers the turns. That is on the list to remove, not a decision.

Kolkrabbi has itEFFORT

The dial picks the model

Elsewhere, effort means thinking tokens on one model. In Kolkrabbi, low, medium, high and max select which model runs the turn and how wide the agent work goes — so cheap work can go to a cheap model without you retyping anything.

Kolkrabbi has itMEASUREMENT

Your own numbers, on your own disk

Every call is appended to a JSONL file you own. /stats shows cost, latency, tokens and your own 1–5 ratings per model. Claude Code shows usage on your account; Kolkrabbi shows it in a file you can grep.

Kolkrabbi has itPRIVACY

No telemetry at all

Claude Code sends operational telemetry unless an organization turns it off. Kolkrabbi contacts a server when you ask it to, and not otherwise — no analytics, no background version check, no cloud sync.

04 / THE TWIST

You can run Kolkrabbi on Claude Code.

The obvious question about this page is why you would use one when you already have the other. You do not have to choose.

How it worksBACKEND

Your own claude, driven as a subprocess

Kolkrabbi's Anthropic backend spawns the claude binary you installed and logged into yourself, unmodified, in a cleared environment, and translates its output into Kolkrabbi's own event stream. Your Claude subscription answers the turn.

What that meansHONEST

In that mode, Claude Code is the agent

It runs its own tools. Kolkrabbi's permission rules and path jail do not gate them, and the interface says so on every provider-executed line rather than once at the start. Kolkrabbi is the front end and the recorder, not the agent.

Why botherRECORD

The same ledger across both

Turns answered by your Claude plan land in the same local stats file as turns answered by an OpenRouter model or a local one, so you can compare them. Subscription turns are labelled API-equiv. and never pooled with metered spend: a Max subscriber's marginal cost is zero, and a number that pretends otherwise is worse than none.
