Compare

Kolkrabbi
vs Codex CLI

Codex CLI is OpenAI's terminal coding agent: Apache-2.0, installed by script, npm, Homebrew or a release binary, and signed into with the ChatGPT plan you already pay for. It reaches local and third-party models through model_providers in config.toml, speaks MCP, and sandboxes the commands it runs. Kolkrabbi is also Apache-2.0 and also reaches local models — the differences are narrower than the marketing on either side suggests, and worth stating precisely.

Every claim below was checked against primary documentation on 2026-09-03. Both projects move quickly. If something here is out of date, it is a bug — say so.

01 / WHERE KOLKRABBI IS BEHIND

What Codex CLI does better.

This section comes first on purpose. A comparison that opens with its own strengths is an advertisement, and you should not trust the rest of it.

Kolkrabbi does notSANDBOX

Codex sandboxes execution; Kolkrabbi does not

Codex has sandbox_mode — read-only, workspace-write, or danger-full-access — with a matching approval policy. Kolkrabbi has permission tiers, a path jail and confirmation rules, but no OS-level sandbox. This is the most substantive gap on this page.

Kolkrabbi does notMCP

No MCP servers

Codex's MCP support is deep: OAuth and bearer auth, per-tool approval modes, timeouts. Kolkrabbi has none yet.

Kolkrabbi does notWINDOWS

macOS and Linux only

Codex runs on Windows through PowerShell. Kolkrabbi cross-builds for Windows in CI and does not support it.

Kolkrabbi does notBACKING

One person against a vendor's team

Codex is OpenAI's own client for OpenAI's models, and it will always know things about them first.

02 / WHERE KOLKRABBI IS AHEAD

What Kolkrabbi does differently.

Not better at everything — different in specific ways, each of which you can check in the source or in the first ten minutes of using it.

Kolkrabbi has itMODELS

Not one vendor's models

Codex reaches other providers through configuration, but it is OpenAI's client and defaults to OpenAI. Kolkrabbi treats every provider as a first-class route, including two subscriptions and a gateway with the whole catalogue behind it.

Kolkrabbi has itSUBSCRIPTIONS

Both subscriptions, one terminal

Codex uses your ChatGPT plan. Kolkrabbi can run turns on your ChatGPT plan and on your Claude plan, by driving each vendor's own CLI as a subprocess, and a gateway model and a plan can trade places mid-session. It never sees or stores either credential. One caveat, because it is the first thing you would hit: starting a session still expects a gateway key even when a plan answers the turns. That is on the list to remove, not a decision.

Kolkrabbi has itEFFORT

The dial picks the model

Low, medium, high and max select which model runs the turn and how wide the agent work goes, rather than only how much thinking one model does.

Kolkrabbi has itMEASUREMENT

Cost, latency and your own ratings, locally

Every call lands in a JSONL file on your disk. /stats turns it into cost per model, latency, token counts and your own 1–5 ratings — the data you need to decide which model is worth its price.

Kolkrabbi has itSIZE

One static binary under 9 MB

No runtime, no package manager, two dependencies in the module graph, and a release whose checksums are verified by the installer and signed with keyless Cosign.

04 / THE HONEST PART

Both of these reach local models.

A lot of comparison pages claim that only their tool can talk to Ollama. That is not true here, and pretending otherwise would make everything else on this page less believable.

CodexLOCAL

ollama and lmstudio are built in

They are reserved provider ids in Codex's configuration, and any other OpenAI-compatible endpoint can be added with base_url and wire_api. vLLM works.

KolkrabbiLOCAL

Ollama is found, not configured

Kolkrabbi uses the Ollama you already have and never installs one. A pulled model appears in /model even while Ollama is idle, and choosing it starts the server for the session. vLLM and LiteLLM connect over an OpenAI-compatible URL.

The real differenceMIXING

What you do with several at once

The gap is not whether a local model is reachable. It is whether the tool is built to move between a local model, a gateway model and a subscription in one session, and to record what each one cost and how good it was. That is the part Kolkrabbi is for.

05 / TRY BOTH

Ten minutes settles more than a table.

Both are one command. Run them on the same repository, on the same task. When we did that with a local 8B model, all three scored zero — the pre-registered benchmark is where side-by-side results will land as they exist.

Install both and judge for yourself. Neither command needs the other uninstalled.
