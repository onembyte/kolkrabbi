Local models

Your models.
Your machine.

Most terminal coding agents assume a card on file. Kolkrabbi does not: it will run a whole session against a model on your own hardware, with no key, no account and nothing leaving the machine. This page is the overview — how it finds a local server, what it refuses to do to your system, and where the honest limits are.

Every command on this page was checked against kolk help on 2026-09-04.

01 / FOUR WAYS IN

Four ways to a local model.

One of them needs no configuration at all. The other three are a single flag.

Zero configOLLAMA

Ollama, found not configured

If a server is already listening on 127.0.0.1:11434, Kolkrabbi adopts it. If not, and the ollama binary is on your PATH, it starts one on a port it picks itself. Your pulled models appear in the /model picker either way.

One flagVLLM

vLLM, over its OpenAI-compatible API

Point --base-url at the server and Kolkrabbi talks to it directly. No key is sent, because there is none to send.

One flagLITELLM

LiteLLM, as a proxy in front of anything

Same flag. LiteLLM is the useful shape when you want one endpoint in front of several backends, local and remote.

One flagANY

Anything that speaks OpenAI

--base-url takes any OpenAI-compatible endpoint. If it answers at /v1, Kolkrabbi will use it.

03 / WHAT IT REFUSES

What Kolkrabbi will not do to your machine.

These are deliberate refusals written into the design, not features that are merely missing. They are the reason it is safe to point at a server you care about.

RefusedINSTALL

It never installs Ollama

Kolkrabbi's own rules forbid curl | sh and sudo, and a floor the product steps over is not a floor. If the binary is missing, it names the command that installs it and lets you run it.

RefusedADOPTION

It never stops a server it did not start

A server already listening is adopted read-only. It might be your shell, or a systemd service holding your sign-in. Kolkrabbi stops only the process it started itself.

RefusedHOST

It only ever probes 127.0.0.1:11434

Never OLLAMA_HOST, which may point at another machine or at ollama.com. If you want a different address, you pass it yourself with --base-url.

RefusedPULLS

It never pulls a model behind your back

A pull is an explicit approval. Cloud models you have not pulled can appear as rows with the exact command visible, but nothing downloads on its own.

HonestDEFAULT

Local is never the zero-config default

With no model chosen, Kolkrabbi picks a free gateway model — because nothing can tell whether your 1.5B local model is a better choice than a 480B free one. Local is always a choice you make.

Kolkrabbi has itKEY

A --base-url session needs no key at all

Verified on a machine with no Kolkrabbi config and no key anywhere: kolk --base-url … -m … goes straight to the endpoint and fails, if it fails, on the connection rather than on a missing credential. Where a key is still expected today is a subscription plan answering the turns; that is a known rough edge and it does not touch this path.

04 / THE POINT

Why do this at all.

A local model is slower and usually weaker than a frontier one. Three reasons it is still worth having in the same terminal.

ReasonCOST

$0.00, on the same ledger

Local turns land in the same local stats file as gateway turns, with a real zero next to them. Over a week that is the clearest picture you will get of what your cloud usage is actually buying you.

ReasonPRIVACY

The code never leaves

No telemetry, no analytics, no background version check, no hosted service. With a local model and no gateway turn, nothing goes anywhere at all.

ReasonMIXING

Cheap work on a cheap model

The effort dial chooses the model. Point low at a local model and max at a frontier one, and routine turns stop costing money without you thinking about it.
