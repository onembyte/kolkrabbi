## 1. Free models & rate limits (docs: /docs/api-reference/limits)
- Identification: `pricing.prompt == "0" && pricing.completion == "0"`, id suffix `:free`.
  Live catalog 2026-08-21: **422 models, 23 free**, nearly all free ones support `tools` +
  `reasoning`; routers `openrouter/auto` and `openrouter/free` exist; model objects carry
  `supported_parameters`, `top_provider`, `per_request_limits`, `default_parameters`,
  `expiration_date`, `knowledge_cutoff` (churn: free variants appear/disappear; some have
  expiration dates — cache the catalog with a TTL and tolerate 404s).
- Limits for `:free` variants: **20 requests/min**; **50 requests/day** if lifetime purchases
  < $10; **1000 requests/day** with ≥ $10 lifetime purchases.
- `GET /api/v1/key` exposes `limit_remaining`, `usage_daily/weekly/monthly`; 429 responses carry
  `X-RateLimit-Limit/Remaining/Reset` headers.
- Data policy: free endpoints often have looser data-collection terms; requests can filter with
  `provider.data_collection: "deny"` or `provider.zdr: true` (account-level defaults exist too —
  exact account settings unverified this session).

## 2. Routing primitives (docs: /docs/features/provider-routing, /docs/features/model-routing)
- **`openrouter/auto`**: classifies the prompt into ~30 task categories, ranks models by
  community spend over a trailing 7-day window, applies your cost-tier preference, routes with
  fallbacks; **session stickiness** prefers the previously selected model while it remains a top
  candidate; no extra fee (you pay the selected model's rate). `openrouter/auto-beta` = early
  track. (The `models` fallback array / `route` param weren't on this page this session —
  re-verify their current form when implementing.)
- **`provider` object**: `order`, `allow_fallbacks` (default true), `require_parameters`,
  `data_collection` ("allow"/"deny"), `zdr`, `enforce_distillable_text`, `only`, `ignore`,
  `quantizations`, `sort` ("price" | "throughput" | "latency", or an object with
  `partition: "none"` to sort globally across several models), `preferred_min_throughput` /
  `preferred_max_latency` (number or percentile object p50/p75/p90/p99 — deprioritize, not
  exclude), `max_price`.
- Default load balancing: filter providers with recent outages (last 30 s), then weight the
  cheapest candidates by **inverse square of price** ($1/M is 9× likelier than $3/M); disabled
  when `sort`/`order` given.
- Suffix shortcuts: **`:nitro`** = `sort: "throughput"` + priority service tier; **`:floor`** =
  `sort: "price"` + flex tier; `:free` = free variant. (`:online`/`:thinking`/`:exacto` not
  re-verified this session.)
- **Per-model endpoints API** — `GET /api/v1/models/{author}/{slug}/endpoints` (probed live):
  each endpoint reports `provider_name`, `context_length`, `max_completion_tokens`,
  `quantization`, `status`, `pricing` (incl. `input_cache_read`, `discount`),
  `supported_parameters`, `supports_implicit_caching`, **`latency_last_30m`**,
  **`throughput_last_30m`**, **`uptime_last_5m/30m/1d`**. → kolk can pick "fastest cheap model"
  or "cheapest capable model" programmatically; the public rankings page has no separate
  documented API — these endpoint stats + the catalog are the programmatic surface.

## 3. Reasoning control (docs: /docs/use-cases/reasoning-tokens)
- Unified request param: `reasoning: { effort: "none"|"minimal"|"low"|"medium"|"high"|"xhigh"|
  "max", max_tokens, exclude (default false), enabled }`. Effort→budget mapping ≈ max/xhigh 95%,
  high 80%, medium 50%, low 20%, minimal 10% (OpenAI/Grok; Gemini 3 maps effort to
  `thinkingLevel`, xhigh→high). `max_tokens` style for Anthropic/Gemini/Qwen (min 1024, max
  128k). Legacy `include_reasoning` maps onto it.
- Streaming: `choices[].delta.reasoning_details` chunks; types `reasoning.summary`,
  `reasoning.encrypted`, `reasoning.text`.
- **Tool-loop requirement:** pass reasoning back via `message.reasoning` or
  `message.reasoning_details`; "The entire sequence of consecutive reasoning blocks must match
  the outputs generated by the model during the original request; you cannot rearrange or modify
  the sequence." → kolk's session store must preserve `reasoning_details` on assistant messages
  (the current prototype drops them — a known gap).

## 4. Cost, usage & caching (docs: /docs/use-cases/usage-accounting, /docs/features/prompt-caching)
- `usage: {include: true}` → exact `usage.cost` in the final stream chunk (prototype already
  uses this); `GET /api/v1/generation?id=` returns authoritative `total_cost`,
  `native_tokens_*`, latency; `GET /api/v1/key` for credits.
- Cached tokens in `usage.prompt_tokens_details`: `cached_tokens` (reads) and
  `cache_write_tokens`.
- Caching per provider through OpenRouter: OpenAI automatic (≥1024 tokens); Anthropic needs
  `cache_control` (top-level auto mode or per-block breakpoints; writes 1.25× 5-min / 2× 1-h,
  reads 0.1×); Gemini 2.5+ implicit (reads 0.25×, 5-min TTL); DeepSeek/Groq/Moonshot/Grok/Z.AI
  automatic; Qwen explicit breakpoints. → kolk should set Anthropic-style breakpoints on the
  system prompt + stable history prefix, and record cache reads/writes in the dashboard.

## 5. Auth UX — OAuth PKCE (docs: /docs/use-cases/oauth-pkce)
- Authorize: `https://openrouter.ai/auth?callback_url=...&code_challenge=...&
  code_challenge_method=S256` (S256 recommended). **Localhost callbacks work on any port** —
  ideal for a CLI. Headless variant: omit `callback_url`, pass `key_label`, user copies the code
  manually. Codes are single-use, expire in 10 minutes.
- Exchange: `POST https://openrouter.ai/api/v1/auth/keys` with `{code, code_verifier,
  code_challenge_method}` → returns a user-controlled API `key`. Revocation happens in the
  user's OpenRouter dashboard (no doc'd revoke endpoint).
- App attribution (docs: /docs/app-attribution): `HTTP-Referer` (the app URL) is **required**
  for attribution/rankings; `X-OpenRouter-Title` sets the display name and only works alongside
  HTTP-Referer. Note: the prototype sends the older `X-Title` header — update to
  `X-OpenRouter-Title` (verify whether both are accepted).

## 6. API surface & errors (docs: /docs/api-reference/errors)
- Errors: 400 bad params · 401 invalid key/expired OAuth · 402 insufficient credits · 403
  moderation/guardrail (with `error.metadata.reasons/flagged_input/provider_name/model_slug`) ·
  408 timeout · 429 rate limited · 502 model down/invalid upstream response · 503 no provider
  matches routing requirements. 429/503 may carry `Retry-After`. Upstream errors are normalized
  into a stable typed **`error_type`** vocabulary — branch on it, not on HTTP status alone.
- **Mid-stream errors**: once streaming starts the 200 is committed; errors arrive as SSE events
  with error details and a completion choice with `finish_reason: "error"` — the client must
  treat that as terminal (the prototype only handles the `error` field, not
  `finish_reason: "error"` — gap).
- Structured outputs: `structured_outputs`/`response_format` appear per-model in
  `supported_parameters` (filter with `provider.require_parameters: true`).

## 7. Recommended defaults for kolk
- Fresh install: build effort tiers from the live free list (free + tools + reasoning, ranked by
  size/ctx/recency), fall back to `openrouter/free`; rotate to the next free model on 429 with a
  per-turn tried-set (see orcli.md); surface the 50/day vs 1000/day ($10) rule in `kolk doctor`.
- Fast lane (titles/summaries/intent): cheapest endpoint with `throughput_last_30m` above a
  threshold via the endpoints API, or `<model>:nitro`; free-first.
- Effort dial: map kolk effort → tier model + `reasoning.effort`
  (quick→low/none, standard→medium, deep→high, ultra→xhigh/max where supported;
  `require_parameters` when reasoning is essential).
- Always send: `usage: {include: true}`, attribution headers, `stream_options.include_usage`;
  store per call: model, endpoint/provider_name, tokens (incl. cached read/write, reasoning),
  cost, TTFT, total ms, finish_reason, error_type → matches the dashboard schema
  (see dashboard.md §4).
- Handle: 402 → stop + `/credits` hint; 429 → rotate/backoff with Retry-After; 503 → relax
  provider filters; mid-stream `finish_reason:"error"` → retry once on another
  provider/model.
