# 12. Sessions, context & memory

Status: hardened on 2026-08-26 · supersedes: — · PLAN.md item 12

## Decision (the short version)

Sessions stay one JSON file each. The dashboard's SQLite plan does not pull sessions with it,
because the repository's dependency budget hard-fails above two third-party modules and Kolkrabbi is
at exactly two — adding SQLite for sessions would break `make check` today, and sessions gain
nothing from a query engine that one process reads one file from.

The real work in this item is context, not storage. Kolkrabbi today has no token accounting against
a model's context window, no compaction, and no handling for a provider refusing an over-long
request. A long session therefore ends in a failed turn with a provider error and no way forward,
and the fast lane — whose own doc comment already advertises "compaction summaries" — is unused.
The design below measures the window from the provider's own reported token counts, compacts at 75%
with the oldest tool traffic dropped first, keeps the pre-compaction messages so the step is
reversible, and treats an overflow error as a trigger to compact and retry once rather than as the
end of the turn.

Memory gains one user-level layer beneath the project file that already exists, with the same size
cap and an explicit command to write to it. Nothing writes to memory on its own.

## Spec

### 1. Storage — unchanged, deliberately

| | Decision |
|---|---|
| Format | One JSON file per session, `<data>/sessions/<id>.json`, atomic save. Unchanged. |
| Schema | `session.Message` as frozen by A10.2. Unchanged. |
| Dashboard | Reads `stats.jsonl`, not sessions. The two stores stay independent. |
| Migration path | If this is ever revisited, A10 already froze a v0 fixture and a translation boundary, so it is a store swap behind `engine.SessionPort`, not a rewrite. |

New fields on the session record, all `omitempty` so existing files stay valid:

```json
{
  "cwd": "/home/me/project",
  "compactions": [
    {"at": "2026-08-26T07:00:00Z", "replaced": 42, "summary_tokens": 380, "snapshot": "<id>.pre-compact-1.json"}
  ]
}
```

### 2. Context accounting

Measured, not estimated, wherever possible:

| Input | Source |
|---|---|
| Window size | `provider.Model.ContextLength` from the catalog, per active model. |
| Current size | `Meta.PromptTokens` from the most recent turn — the provider's own count of what it just read. |
| Before the first turn of a resumed session | Estimate at 4 characters per token, used **only** as a floor to decide whether to compact before sending. |
| Unknown window | No compaction. Kolkrabbi does not invent a limit it was not told. |

`cache_read_tokens` (B12.14) is *not* subtracted: a cached prompt still occupies the window.

### 3. Compaction

- **Threshold:** compact when the next request is projected to exceed **75%** of the window. The
  remaining quarter has to hold the reply and at least one tool round; compacting at 95% leaves a
  session that compacts and then immediately fails anyway.
- **Never mid-loop.** Compaction happens at a turn boundary only. Compacting between a tool call and
  its result would orphan the call, which is the exact damage A10's repair exists to undo.
- **Order of sacrifice**, stopping as soon as the projection fits:
  1. Tool *results* older than the last two turns → replaced by `[tool output dropped: <n> chars]`.
     They are the bulk of a coding session and are already capped at 12 000 characters each.
  2. Tool *calls* older than the last two turns → replaced by a one-line record of what ran.
  3. The remaining older span → one fast-lane summary.
- **Summary contract.** The summary must preserve, in this order: the user's goal, decisions taken,
  files created or modified, commands whose results still matter, and open work. It must not
  preserve conversational texture. It is generated by the fast lane (M8.4), which is zero-cost when
  the session model is free.
- **Reversible.** The pre-compaction message list is written to `<id>.pre-compact-<n>.json` before
  the session is rewritten. `/rewind --compact` restores the most recent one.
- **Visible.** Compaction prints one line: `compacted 42 messages into a 380-token summary`. It is
  never silent: a user who cannot see it happen cannot explain why the model forgot something.

### 4. Overflow as a recoverable error

A provider rejecting an over-long request is currently an unclassified failure. It becomes:

1. Classify the provider error as context overflow (`KindContextOverflow`, already named in
   `docs/plan/04` for the Claude adapter).
2. Compact once, at the same turn boundary, using the rules above.
3. Retry the turn exactly once. A second overflow is a hard error with the measured sizes in the
   message.

### 5. Session commands

| Command | Behaviour |
|---|---|
| `kolk sessions` | Unchanged list. Adds a `CWD` column. |
| `kolk sessions search <text>` | Case-insensitive match over title and message content, newest first. |
| `kolk sessions rename <id> <title>` | Replaces the auto-title. |
| `kolk sessions fork <id>` | New id, copied messages, title `<old> (fork)`. The original is untouched. |
| `kolk sessions export <id> [--json\|--md]` | Markdown by default: a readable transcript, tool bodies elided. |
| `kolk -r` | Resumes the most recent session **for the current directory** when one exists, otherwise the most recent overall, and says which it chose. |
| `/compact` | Manual compaction at a turn boundary. |

Auto-titling moves to the fast lane (already built for exactly this) instead of the first line of
input, once a session has two turns.

### 6. Memory layers

| Layer | Path | Cap | Written by |
|---|---|---|---|
| Project | `KOLKRABBI.md` then `AGENTS.md` in the working directory (existing) | 16 KiB (existing) | The user, or `/remember --project` |
| User | `<config>/memory.md` (new) | 16 KiB | The user, or `/remember` |

Precedence: both are appended to the system prompt, user layer first, project second, so a project
statement wins a contradiction by being nearer the task. Over-cap files are truncated at a line
boundary with a visible marker rather than silently cut.

**The agent never writes memory on its own.** `/remember <text>` appends one line, prints what it
wrote and where. A model that can edit its own standing instructions unprompted is a model whose
behaviour cannot be explained by reading the repository.

## Rationale

- **Storage.** `scripts/check-budgets.sh` fails the build above two third-party modules and the root
  graph has exactly two (`golang.org/x/sys`, `golang.org/x/term`). A12.5 plans to raise that ceiling
  deliberately *for the dashboard*; borrowing that raise for sessions would spend a hard budget on a
  problem sessions do not have. One process reads one session at a time.
- **Measured tokens beat estimated ones.** The provider reports what it actually read. An estimator
  that is 20% wrong either compacts sessions that did not need it or fails the ones that did.
- **Tool output first.** In a coding session it is most of the bytes and the least of the meaning,
  and it is already truncated at 12 000 characters, so dropping it is cheap and legible.
- **Reversible and visible.** Compaction is the one operation that makes the model forget. Both
  properties exist so a surprising answer can be traced to it.

## Alternatives rejected

- **SQLite for sessions now** — breaks the dependency budget gate today, for capability sessions do
  not use.
- **Compact at 95% of the window** — leaves no room for the reply; the session compacts and fails
  in the same turn.
- **Estimate tokens by character count** — available before the first turn only, and wrong enough to
  either waste summaries or miss overflows.
- **Summarise everything into one rolling summary** — loses the recent verbatim turns that the model
  needs most, and compounds its own paraphrase every cycle.
- **Let the agent write memory when it decides something is important** — standing instructions that
  change without a user action cannot be reviewed.
- **Silent compaction** — cheaper to build and impossible to debug from the outside.

## Risks & open questions

- **Summary quality is unmeasured.** A bad summary is a session that quietly loses a decision →
  mitigation: keep the last two turns verbatim, keep the pre-compaction snapshot, and print the
  token counts so a lossy compaction is visible.
- **`ContextLength` is only as good as the catalog.** A stale or missing entry means no compaction
  → mitigation: no window, no compaction, and say so once per session rather than guessing.
- **Fast-lane cost on paid models.** M8.4 caps the fast lane at $0.15/1M tokens, so a summary is
  cheap but not free → open: whether `/compact` on a paid fast lane should confirm first.
- **Per-directory resume needs a `cwd` on old sessions.** Sessions written before this change have
  none → mitigation: they simply never match a directory and remain reachable by `-s` and by the
  global `-r` fallback.
